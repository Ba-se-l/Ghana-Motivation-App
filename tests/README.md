## 1. المعمارية التقنية لحزمة الاختبارات

تعتمد حزمة الاختبارات على **تقنية النقل المزدوج الذكي (Smart Dual-Transport Strategy)** داخل الملف `tests/config.py`:
1. **نمط السيرفر الحي (Live Server Mode):** يقوم العميل بفحص المنفذ الافتراضي `http://127.0.0.1:8000`. إذا وجد السيرفر قيد التشغيل (عبر Uvicorn)، يقوم بتوجيه كافة الطلبات كـ HTTP حقيقي عبر بطاقة الشبكة لاختبار دورة حياة السيرفر الفعلية.
2. **نمط المحاكاة المباشرة في الذاكرة (In-Memory ASGI Fallback):** إذا لم يكن السيرفر يعمل، أو نسي المطور تشغيله قبل بدء الاختبارات، لا تفشل الاختبارات! بل يتم استخدام `httpx.ASGITransport(app=main.app)` للتواصل مباشرة مع تطبيق FastAPI في الذاكرة بنفس السرعة والدقة.
3. **الاستقلالية التامة (Zero-Framework Lock-in):** الاختبارات مكتوبة باستخدام بايثون الحديثة القياسية (Async/Await) ومكتبة `httpx`، دون الحاجة الإلزامية لتثبيت `pytest`، مما يتيح لأي مطور تشغيلها فوراً عبر أمر بايثون العادي.

## 2. المتطلبات الأساسية للتشغيل (Prerequisites)

قبل تشغيل أي ملف اختبار، تأكد من توفر الآتي:

1. **تفعيل البيئة الافتراضية للباثيون:**
   ```powershell
   # على نظام Windows PowerShell:
   .\.venv\Scripts\Activate.ps1
   ```
2. **تثبيت حزم المشروع:**
   يجب التأكد من تثبيت حزمة `httpx` وحزم المشروع الأساسية:
   ```bash
   pip install -r requirements.txt
   ```
3. **جاهزية قاعدة البيانات وبذر الاقتباسات (Seeding):**
   ملف الاقتباسات يتطلب وجود بيانات الاقتباسات الـ 365 في قاعدة البيانات. إذا كانت قاعدة البيانات جديدة أو فارغة، قم بتشغيل سكربت البذر:
   ```bash
   python scripts/seed_quotes.py
   ```
4. **(اختياري ومستحسن) تشغيل السيرفر الرئيسي:**
   إذا أردت فحص السيرفر المباشر عبر الشبكة، شغّله في نافذة طرفية (Terminal) منفصلة:
   ```bash
   python main.py
   # أو
   uvicorn main:app --reload --port 8000
   ```

## 4. تفصيل ملفات الاختبار (متى ولماذا تشغل كل ملف؟)

### 01. ملف اختبار المصادقة والجلسات (`test_01_auth.py`)
* **المسار:** `tests/test_01_auth.py`
* **متى تشغله؟**
  - عند تعديل أي ملف في `GhanaMotivationApp/modules/auth/`.
  - عند تغيير منطق توليد التوكنات (JWT)، خوارزميات التشفير (Argon2id)، أو نموذج تسجيل الدخول.
* **ماذا يختبر بالظبط؟**
  1. `POST /api/v1/auth/register`:
     - تسجيل مستخدم جديد بالكامل.
     - رفض تكرار نفس البريد الإلكتروني (إرجاع كود `409 Conflict`).
     - رفض كلمات المرور الضعيفة أو غير المتطابقة مع قيود Pydantic (إرجاع كود `422`).
  2. `POST /api/v1/auth/login`:
     - تسجيل الدخول ببيانات صحيحة والحصول على التوكنات (JSON Body).
     - رفض كلمة المرور الخاطئة (إرجاع كود `401 Unauthorized`).
     - رفض محاولة الدخول ببريد غير مسجل أساساً (إرجاع كود `401 Unauthorized`).
  3. `POST /api/v1/auth/refresh`:
     - تدوير التوكن وتجديده (Token Rotation).
     - **كشف وإحباط سرقة التوكنات (Token Reuse Detection):** تجربة استخدام نفس التوكن القديم مرة ثانية، والتحقق من أن النظام يكتشف الهجوم ويلغي الجلسة مباشرة (`401 Unauthorized`).
  4. `POST /api/v1/auth/logout`:
     - إلغاء الجلسة الحالية من قاعدة البيانات.
  5. `POST /api/v1/auth/logout-all`:
     - تسجيل الخروج الجماعي وإلغاء جميع جلسات المستخدم من كافة الأجهزة.

---

### 02. ملف اختبار المستخدم والأمان (`test_02_users.py`)
* **المسار:** `tests/test_02_users.py`
* **متى تشغله؟**
  - عند تعديل أي جزء من `GhanaMotivationApp/modules/user/`.
  - عند إجراء تغييرات في حسابات الفترة التجريبية (Trial period) أو شروط التحقق من الأمان.
* **ماذا يختبر بالظبط؟**
  1. `GET /api/v1/users/me`:
     - محاولة جلب الملف الشخصي بدون توكن (التأكد من المنع بكود `401 Unauthorized`).
     - جلب بيانات الملف الشخصي بنجاح عند إرسال توكن صالح (`200 OK`).
  2. `GET /api/v1/users/status`:
     - التحقق من تفاصيل الاشتراك، الأيام المتبقية في الفترة التجريبية (`trial_days_left`)، وحالة الحساب التجريبي والمميز (`is_trial_active`, `is_premium`).
  3. `PATCH /api/v1/users/me/password`:
     - محاولة تغيير كلمة المرور بتقديم كلمة المرور القديمة بشكل خاطئ (التأكد من الرفض بكود `401 Unauthorized`).
     - تغيير كلمة المرور بنجاح (`200 OK`).
     - التحقق من إبطال كلمة المرور القديمة ومنع استخدامها لتسجيل الدخول مجدداً.
     - التحقق من نجاح تسجيل الدخول بكلمة المرور الجديدة.

---

### 03. ملف اختبار المدفوعات والـ Webhooks (`test_03_payments.py`)
* **المسار:** `tests/test_03_payments.py`
* **متى تشغله؟**
  - عند تعديل تكامل بوابة Paystack أو ملفات `GhanaMotivationApp/modules/payment/`.
  - عند فحص الأمان المالي والحدود الصفرية للثقة (Zero-Trust Financial Boundaries).
* **ماذا يختبر بالظبط؟**
  1. `POST /api/v1/payments/initialize`:
     - رفض الطلب غير المصادق عليه (`401`).
     - إنشاء مرجع دفع فريد بسعر النظام الرسمي الحصري المسجل بالسيرفر (`200 OK` + رابط تفويض Paystack).
  2. `GET /api/v1/payments/verify`:
     - رفض الفحص بدون مصادقة (`401`).
     - **حماية الملكية (Ownership Boundary):** محاولة المستخدم (ب) فحص أو الاستيلاء على معاملة تخص المستخدم (أ) — التحقق من الرفض التام بكود `403 Forbidden`.
     - التحقق الناجح من المعاملة عبر Mock Paystack، وترقية المستخدم لحساب Premium.
     - التأكد الفعلي عبر `GET /users/status` أن `is_premium=True`.
     - **تحقيق معيار تكرار الطلب (Idempotency):** فحص نفس المعاملة الناجحة مرة أخرى، والتأكد من إرجاع استجابة آمنة دون أخطاء أو مضاعفة الاشتراكات.
  3. `POST /api/v1/payments/webhook`:
     - إرسال Webhook بتوقيع مزور أو خاطئ — التأكد من الرفض الفوري بكود `401 Unauthorized`.
     - إرسال Webhook بتوقيع HMAC-SHA512 مشفر بالمفتاح السري — التأكد من قبول ومعالجة الحدث بنجاح (`200 OK`).

### 04. ملف اختبار الاقتباسات والمزامنة (`test_04_quotes.py`)
* **المسار:** `tests/test_04_quotes.py`
* **متى تشغله؟**
  - عند تعديل `GhanaMotivationApp/modules/quote/`.
  - عند تغيير منطق التخزين المؤقت دون اتصال (Offline Caching) أو ترتيب وجلب الاقتباسات اليومية.
* **ماذا يختبر بالظبط؟**
  1. `GET /api/v1/quotes/today`:
     - جلب اقتباس اليوم المتوافق بدقة مع رقم اليوم الحالي من السنة (UTC Day of Year 1-365).
  2. `GET /api/v1/quotes/random`:
     - جلب اقتباس عشوائي صالح ونشط.
  3. `GET /api/v1/quotes/batch`:
     - طلب حزمة نطاق أسبوعي (الأيام من 1 إلى 7) والتأكد من استرجاع 7 عناصر متسلسلة بدقة.
     - طلب حزمة يوم فردي (100 إلى 100) والتأكد من استرجاع عنصر واحد فقط.
  4. **فحص قيود الإدخال ومعايير Pydantic/FastAPI Validation (كود `422`):**
     - طلب `start_day=0` (الحد الأدنى 1) -> يرجع `422 Unprocessable Entity`.
     - طلب `end_day=366` (الحد الأقصى 365) -> يرجع `422 Unprocessable Entity`.
     - طلب بدون معاملات استعلام (Missing Query Params) -> يرجع `422`.
     - تمرير نصوص بدل الأرقام (Invalid Types) -> يرجع `422`.

## 5. دليل معالجة الأخطاء والتشخيص (Troubleshooting & Diagnostics)

### ماذا لو فشل الملف X؟

#### السيناريو 1: فشل `test_04_quotes.py` بكود `404 Not Found`
* **السبب:** جدول الاقتباسات `quotes` فارغ في قاعدة البيانات أو لم يتم بذر الاقتباس لليوم الحالي.
* **الحل:**
  ```bash
  python scripts/seed_quotes.py
  ```
  ثم أعد تشغيل الفحص.

---

#### السيناريو 2: فشل `test_01_auth.py` في فحص `test_refresh_token` بكود `401`
* **السبب:** ربما انتهت صلاحية التوكن، أو هناك اختلاف في المناطق الزمنية (Timezone Offsets) في قاعدة بيانات SQLite.
* **الحل:** تم توحيد كافة التواريخ باستخدام `timezone.utc`. تأكد من أن ساعة جهازك مضبوطة، وتأكد من أن ملف `GhanaMotivationApp/core/security.py` يستخدم نفس المتغيرات السرية.

---

#### السيناريو 3: فشل في `test_03_payments.py` عند `payments/initialize`
* **السبب:** خطأ في إعدادات العملة أو السعر في ملف الإعدادات.
* **الحل:** تأكد من وجود المتغيرات التالية في ملف `.env` أو إعدادات التطبيق الافتراضية:
  ```env
  PAYSTACK_SECRET_KEY="sk_test_mock..."
  SUBSCRIPTION_PRICE_GHS=1000
  ```

---

#### السيناريو 4: فشل الاتصال بالسيرفر (Connection Refused)
* **الملاحظة:** تم تصميم حزمة الاختبارات بحيث تتجاوز هذا الخطأ تلقائياً عبر نمط الـ ASGI Fallback.
* إذا ظهرت رسالة:
  `[INFO] Live server not detected at http://127.0.0.1:8000. Using in-memory ASGI transport.`
  فهذا طبيعي ومقصود، وتعني أن الاختبارات تعمل بنجاح داخلياً دون الحاجة لفتح منفذ شبكة.

### معاني رموز الاستجابة (HTTP Status Codes) أثناء الفحص

| الرمز (Code) | المعنى التقني | متى نتوقعه في الاختبارات؟ |
|---|---|---|
| **`200 OK`** | نجاح العملية | عند استرجاع البيانات أو إتمام المدفوعات وتحديث الملف. |
| **`201 Created`** | تم إنشاء المورد | عند تسجيل مستخدم جديد في `/auth/register`. |
| **`401 Unauthorized`** | غير مصرح | عند محاولة الدخول بكلمة سر خطأ، توكن منتهي، أو توقيع Webhook غير سليم. |
| **`403 Forbidden`** | ممنوع الوصول | عند محاولة مستخدم التحقق من معاملة دفع لا يملكها (Ownership Mismatch). |
| **`404 Not Found`** | غير موجود | إذا كان مسار الـ Endpoint خاطئاً أو الاقتباس المطلوب غير موجود. |
| **`405 Method Not Allowed`** | طريقة HTTP غير مسموحة | مثلاً استخدام `PUT` بدلاً من `PATCH` في تغيير كلمة المرور. |
| **`409 Conflict`** | تعارض بيانات | عند محاولة تسجيل نفس البريد الإلكتروني المسجل مسبقاً. |
| **`422 Unprocessable Entity`** | خطأ في بنية البيانات | عند إرسال رقم يوم خارج النطاق (أقل من 1 أو أكثر من 365). |
| **`500 Internal Server Error`** | خطأ غير معالج في السيرفر | **مؤشر خطير:** يجب مراجعة سجلات السيرفر فورا (Terminal logs). |

## 6. التهيئة المتقدمة وتغيير إعدادات السيرفر

إذا كان السيرفر يعمل على منفذ أو رابط مختلف (مثلاً في بيئة Staging أو Docker):

يمكنك توجيه الاختبارات لفحص السيرفر المخصص بسهولة عبر تمرير متغير البيئة `TEST_SERVER_URL`:

```powershell
# على Windows PowerShell:
$env:TEST_SERVER_URL = "http://127.0.0.1:8080"
python tests/run_all_tests.py

# على Linux / macOS / Bash:
TEST_SERVER_URL="http://staging.example.com" python tests/run_all_tests.py
```

> **ملاحظة معمارية للمطورين:**
> حزمة الاختبارات هذه تمثل خط الدفاع الأول وضمان استقرار السيرفر بنسبة 100%. يُوصى بتشغيل `python tests/run_all_tests.py` قبل إجراء أي عملية Commit أو Push للكود.
